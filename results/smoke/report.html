How to read this page
Each grid is one measurement: rows are models, columns are the three KV cache types. A cell's number is that arm's result. Colour always means the same thing: green = best, red = worst. On the retrieval and code grids best means highest; on the two loop grids best means lowest, and those grids are scaled to the observed range so small differences are visible. Each grid prints its own scale. Hover any cell for the exact value.
The loop numbers come in two flavours, and they differ: any verdict includes a compression heuristic that fires on formulaic prose such as a manual generated from twelve fixed rules, while structural repetition counts only samples with a repeated line, repeated n-gram, repeated 200-character block or a repeating tail cycle — i.e. the thing that actually looks like a loop. Read the structural grid as the finding and the "any verdict" grid as an upper bound.
What the tabs hold: Matrix — the verdict, three grids of level-and-change, decode speed, and how often two arms gave the identical answer. Tasks — one dot plot per task: three dots per model, one per KV type, on a 0–100 axis, so overlapping dots mean "the KV type changed nothing here". Loops — structural repetition per arm as bars, then a card for every sample the detector flagged, with the repeated text highlighted.
Three facts that make the numbers honest: differences of a few points are noise; a single code task can swing by tens of points on one design decision, so check the per-task dot plots before reading a score delta as damage; and a score that falls because an arm hit the generation ceiling is truncated output, not wrong output. The prose summary, with the caveats for this run written out, is docs/RESULTS.md.

What we found

Best combination on this run: qwen36-35b with a q4_0 cache — 81.2 out of 100, 0/4 structural-loop samples, 45.6 tokens/second, 9541 MiB of graphics memory with 26 layers of the model kept in system RAM.
How sure are we, and how the ranking works
No other arm is comparable on this result, so the ranking is descriptive only. Capability = the average of the retrieval score and the code score; ties go to the arm with fewer repeating samples, then to the faster one; every paired test clusters the three reps of a task and corrects across all 42 comparisons, so nothing here can separate on a handful of correlated samples.
